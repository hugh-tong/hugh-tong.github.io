# 单篇文章整改模板

复制下面的任务块到对应 PR/commit 说明或 TODO 中。不是所有文章都需要相同篇幅，但技术结论必须有证据。

## 基本信息

- 文件：`source/_posts/<slug>.md`
- 处置：补全 / 合并 / 拆分 / 归档 / 仅校正
- 优先级：P0 / P1 / P2 / P3
- 目标读者：
- 适用软件与版本：
- 最后验证日期：

## 修改前判断

- 这篇文章解决的具体问题是什么？
- 是否与现有文章重复？
- 原始资料、测试环境和示例文件是否仍可取得？
- 当前 URL 是否可能已有外部引用？
- 是否包含个人路径、主机名、内部项目名、凭据或未授权素材？

## 建议正文结构

1. **问题与结论**：读者为什么需要这篇文章，先给可执行结论。
2. **适用范围**：软件发行线、版本、操作系统、关键依赖和验证日期。
3. **原理或依据**：公式、源码路径、官方文档或论文；区分事实、推断和经验。
4. **最小可复现步骤**：输入、命令、配置、预期输出。
5. **验证结果**：日志、数值、图表或失败对照，说明判断标准。
6. **限制与常见错误**：哪些场景不适用，跨版本差异是什么。
7. **参考资料**：完整、稳定、可定位的来源。

## 完成检查

- [ ] 已移除占位文字、AI 对话口吻和未完成标记。
- [ ] 已去标识化日志和路径，且未引入凭据。
- [ ] 每个关键结论都有来源或实测证据。
- [ ] 命令从干净环境或最小案例运行过。
- [ ] 图片为自制或有明确使用许可，含替代文字和说明。
- [ ] front matter 完整，旧 URL 的处置已考虑。
- [ ] `npm run check:source` 通过。
- [ ] `npm run verify` 通过。
- [ ] Butterfly 与 NexT 人工预览无异常。
