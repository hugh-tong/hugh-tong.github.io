> 本目录只记录整改任务，不代表文章内容已经验证。执行时应逐篇修改、逐篇复核，不用 AI 自动批量补正文。

## 审计结论

当前内容问题不是单一的“文章太短”，而是四类问题混在一起：

1. **P0：隐私与正确性**——真实本机用户名、主机名和项目目录残留；个别公式常数、版本说明和部署流程已经错误或过时。
2. **P1：公开占位内容**——21 篇标题或标签明确标注“占位”，另有空白测试页、未完成文章和 PDF 素材标记。
3. **P1：文本来源与表达**——多篇文章保留了 AI 对话结尾、第二人称问答、未经消化的摘录或外链图片。
4. **P2：元数据与长期维护**——基线有 14 篇缺少 `description`，P0 已补齐 5 篇，当前剩 9 篇；此外还有标签重复、主题重叠和旧文章缺少适用版本的问题。

本次扫描**没有发现**已提交的私钥、GitHub token、真实邮箱或 RFC 1918 内网 IPv4 地址。`127.0.0.1:7890`、`your_email@example.com` 等属于示例，不按泄密处理。

## 优先级定义

| 优先级 | 含义 | 处理时限 |
|---|---|---|
| P0 | 可能泄露环境信息、误导读者执行错误操作，或存在明确技术错误 | 下一次发布前 |
| P1 | 公开占位、未完成、AI 对话残留、来源/版权不清 | 完成 P0 后分主题处理 |
| P2 | 描述、标签、结构、语言和旧文维护性问题 | 随主题批次清理 |
| P3 | 可选增强，如配图、性能实测、跨版本对照 | 有可复现证据时再做 |

## 每篇文章的完成标准

参考 [文章整改模板](./article-remediation-template.md)。文章只有同时满足以下条件，才从 TODO 中勾掉：

- [ ] 标题不再含“占位”“还没写完”，正文无 `TODO`、`PDF 素材` 或聊天式收尾。
- [ ] 开头说明问题、适用对象和结论；技术文章明确软件发行版、版本和验证日期。
- [ ] 命令、配置、公式和结论由官方文档、论文、源码或实际运行记录支持。
- [ ] 外部材料经过转述并标注来源；不盗链图片，不大段复制第三方正文。
- [ ] 日志和示例已去除用户名、主机名、组织名、真实项目名及绝对路径。
- [ ] 至少有一个可复现示例，或明确标记为“资料索引/阅读笔记”而不是教程。
- [ ] front matter 包含有效的 `title`、`date`、`description`、`categories`、`tags`；标签无重复。
- [ ] `npm run check:source` 和 `npm run verify` 通过，并人工预览两套主题下的文章页。

## 执行约束

- 只在 `dev_tttt` 修改文章；`main`、`master` 不手改。
- 一次提交只处理一个主题或一个小系列，避免 122 篇文章的大爆炸式改写。
- 修改旧 URL 时优先保留原文件名；若合并文章，先确认是否有站内/站外引用，再决定保留索引页、添加重定向或下线。
- 对不确定的技术说法先删除或标注“待验证”，不能让流畅文字替代证据。
- 从当前版本删除敏感字符串不会抹除 Git 历史；若确认历史中存在真正凭据，应先轮换凭据，再单独评估历史重写。
